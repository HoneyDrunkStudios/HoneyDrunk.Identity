## Code Review Rules

Apply the [shared review criteria](https://github.com/HoneyDrunkStudios/HoneyDrunk.Standards/blob/main/HoneyDrunk.Standards/docs/CONVENTIONS.md#code-review) to changed behavior, using the repository boundaries above. Report actionable findings with the failing path, concrete impact and a small corrective action; disclose unavailable evidence. These rules grant no cross-repository access or merge authority.

- Review the actual selected revision and its contracts; merged source is not evidence of runtime deployment or package publication. Keep account issuance/lifecycle here and shared token validation in Auth. Preserve documented API/event contracts and provider-independent boundaries.
- For implementation changes, trace account/tenant ownership through link/unlink, deletion, replay and concurrent requests. Flag authentication bypass, cross-account mutation, secret exposure or lifecycle delivery acknowledged before its durable/broker contract is satisfied.
- Use the implementation branch's schema, lifecycle and verification contracts for failure-path, authorization, transaction and consumer tests. Apply the shared simple .NET layers and existing SQL ownership; do not infer hosting, migration execution or deployment approval from a source change.
